Modelo de entidades JPA · Instituto

Diagrama de clases del proyecto de ejemplo de la UD3 (Acceso a Datos, DAM2): ciclos formativos, cursos, módulos, alumnos y matrículas. Pulsa sobre una entidad o una relación del diagrama para ver su explicación.

Cómo leer el diagrama

Caja = entidadUna clase Java con @Entity. Cada objeto se guarda como una fila de una tabla con el mismo nombre.
Atributo subrayado = clave primariaLleva @Id. En Alumno y Matricula la genera la BD (@GeneratedValue); en el resto es un código real (DAM2, MP0486…).
Flecha = quién conoce a quiénLa flecha sale de la clase que tiene el atributo y apunta a la otra. Curso → Ciclo significa que Curso tiene un atributo ciclo.
Doble flecha = bidireccionalLas dos clases se conocen: alumno.getMatriculas() y matricula.getAlumno().
Cardinalidad: 1 y *Se lee desde cada extremo: «un curso tiene * (muchos) módulos» y «un módulo está en * cursos».
Texto de la relaciónNombre del atributo Java (modulos) y anotación JPA que lo mapea (@ManyToMany).

Las entidades

Ciclo

Tabla Ciclo · PK natural codigo

Un ciclo formativo completo. Ejemplo: D3IFC000200, DAM, Desenvolvemento de aplicacións multiplataforma, grado superior, 2000 h.

Curso

Tabla Curso · PK natural codigo

Cada uno de los cursos de un ciclo: DAM1, DAM2, DAW1… Sabe a qué ciclo pertenece y qué módulos tiene.

Modulo

Tabla Modulo · PK natural codigo

Un módulo profesional, p. ej. MP0486 Acceso a datos, 220 h, 8 sesiones/semana. Se guarda una sola vez aunque se imparta en varios cursos.

Alumno

Tabla Alumno · PK autonumérica id

Datos personales del alumno. No tiene curso: el curso cambia cada año, así que lo indica cada matrícula.

Matricula

Tabla Matricula · PK autonumérica id

Une a un alumno con un curso académico (2026-2027): el curso en que se matricula y los módulos que cursa, que pueden ser solo algunos o incluir pendientes de otro curso del mismo ciclo.

Restricción UNIQUE: una sola matrícula por alumno y curso académico.

Las relaciones

N:1Curso → Ciclo

Muchos cursos pertenecen a un ciclo
// en Curso
@ManyToOne
private Ciclo ciclo;

En la BD: columna ciclo_codigo en Curso (clave ajena).

N:MCurso → Modulo

Un curso tiene muchos módulos; un módulo puede estar en varios cursos
// en Curso
@ManyToMany
@JoinTable(name = "Curso_Modulo",
  joinColumns = @JoinColumn(name = "curso_codigo"),
  inverseJoinColumns = @JoinColumn(name = "modulo_codigo"))
private List<Modulo> modulos;

En la BD: tabla intermedia Curso_Modulo. Ejemplo: Linguaxes de marcas está en ASIR1, DAM1 y DAW1.

1:NAlumno ↔ Matricula

Un alumno tiene muchas matrículas (una por año) · bidireccional
// en Matricula (lado propietario: tiene la FK)
@ManyToOne(optional = false)
private Alumno alumno;

// en Alumno (lado inverso)
@OneToMany(mappedBy = "alumno",
           cascade = CascadeType.REMOVE)
private List<Matricula> matriculas;

En la BD: solo la columna alumno_id en Matricula. mappedBy evita una segunda relación; cascade REMOVE borra las matrículas al borrar el alumno.

N:1Matricula → Curso

Cada matrícula es de un curso principal
// en Matricula
@ManyToOne(optional = false)
private Curso curso;

En la BD: columna curso_codigo en Matricula. Permite listar los alumnos de DAM2 en 2026-2027.

N:MMatricula → Modulo

Los módulos concretos que cursa el alumno ese año
// en Matricula
@ManyToMany
@JoinTable(name = "Matricula_Modulo", ...)
private List<Modulo> modulos;

En la BD: tabla intermedia Matricula_Modulo. Pueden ser módulos de otro curso del ciclo (pendientes); MatriculaDao lo valida.

Un ejemplo con datos

Uxía está en 2º de DAM en 2026-2027, pero le quedó pendiente Bases de datos de 1º. Así quedan sus datos:

  1. Alumno → una fila: id=5, nombre=Uxía, apellidos=Castro Varela.
  2. Matricula → dos filas, una por curso académico: (1, alumno_id=5, 2025-2026, DAM1) y (2, alumno_id=5, 2026-2027, DAM2).
  3. Matricula_Modulo → la matrícula 2 tiene los 10 módulos de DAM2 más MP0484 (Bases de datos, de DAM1): 11 filas, 1227 horas.
  4. En Java basta con matricula.getModulos().add(basesDeDatos); al hacer commit, JPA inserta la fila en la tabla intermedia.

Tablas que genera JPA en la base de datos

5 entidades producen 7 tablas: las dos relaciones @ManyToMany necesitan una tabla intermedia cada una.

Comprueba que lo has entendido

¿Por qué Alumno no tiene un atributo curso?

Porque un alumno cambia de curso cada año y puede tener módulos de dos cursos a la vez. El curso es un dato de cada Matricula, no del alumno.

¿Qué tabla hay que consultar para saber en qué cursos se imparte MP0373?

Curso_Modulo. En JPQL no se nombra la tabla: SELECT c FROM Curso c JOIN c.modulos m WHERE m.codigo = 'MP0373'.

¿Qué ocurre al borrar un alumno con dos matrículas?

Por cascade = REMOVE, JPA borra primero sus filas de Matricula_Modulo y sus 2 matrículas, y después el alumno. Sin la cascada, la clave ajena alumno_id impediría el borrado.

Si quisiéramos guardar la nota de cada módulo matriculado, ¿dónde iría?

No cabe en @ManyToMany, porque la tabla intermedia no puede tener columnas propias. Habría que crear una entidad MatriculaModulo (matricula, modulo, nota) con dos relaciones @ManyToOne.

¿Por qué Matricula.modulos es LAZY y qué problema puede dar?

Las colecciones (@OneToMany, @ManyToMany) se cargan por defecto solo cuando se recorren. Si se recorren con el EntityManager ya cerrado, salta LazyInitializationException; por eso MatriculaDao usa JOIN FETCH.
